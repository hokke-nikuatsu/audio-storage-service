# ADR-0006: cc-sdd の SKILL.md は、リポジトリの規約と直接ぶつかる箇所に限り1行単位で書き換える

## 背景と課題

ADR-0002 では、cc-sdd のチューニングはテンプレートとルールで行い、SKILL.md 本体は書き換えないと決めた。しかし `/kiro-impl` は、SKILL.md に書かれた `feat(<feature-name>): <task description>` の形で、実装のタスクごとに自分でコミットを作る。この形は作業の進め方の規約にあるコミットの書式（prefix の一覧と、「〜する」で言い切る要約）と食い違い、テンプレートやルールでは直せない。SKILL.md を書き換えるか、規約に例外を設けるかを決める必要がある。

## 検討した選択肢

### 規約に `/kiro-impl` のコミットを例外として書く

- 良い点: cc-sdd に手を入れず、ADR-0002 の決定のままでよい
- 悪い点: 実装のコミットだけ書式が違い、履歴がそろわない。コミットのタイトルを機械でチェックするときに例外が要る

### SKILL.md の食い違う箇所を、規約に従うよう書き換える

- 良い点: 実装のコミットも規約と同じ書式になり、チェックに例外が要らない
- 悪い点: cc-sdd をアップグレードすると上書きされ、再適用が要る

## 決定

「SKILL.md の食い違う箇所を、規約に従うよう書き換える」を選ぶ。実装のコミットは履歴の大半を占めるので、そこだけ書式が違うと、規約とチェックの両方に例外が残り続けるため。

- SKILL.md を書き換えるのは、既定の動きがこのリポジトリの規約と直接ぶつかり、テンプレートやルールでは直せない箇所に限る。書き換えは1行単位にとどめ、規約の中身は書き写さずに正の置き場を参照させる
- 書き換えた箇所には ADR-0002 と同じく `project-override` の印を付け、書き換えたファイルは `.gitattributes` で差分の折りたたみの対象から外す
- この決定は、ADR-0002 の「SKILL.md 本体は書き換えない」を変更する。ADR-0002 のほかの決定は有効なまま。ADR-0002 が SKILL.md の書き換えを退けた理由（変更箇所が多く、アップグレードで壊れる）は、書き換えを1行単位に限ることで小さくする

## 影響

- 良い点: cc-sdd が作るコミットも含めて、コミットの書式が1つになる
- 受け入れたトレードオフ: cc-sdd をアップグレードすると、書き換えた行が上書きされる。ADR-0002 と同じく、`project-override` の印と git の差分を手がかりに再適用する

## 見直し条件

- SKILL.md を書き換えた箇所が5か所を超えたら、cc-sdd に手を入れ続けるか、その skill を自前の skill に置き換えるかを再検討する
- cc-sdd がコミットの書式を設定で変えられるようになったら、書き換えをやめて設定に移す

## 反映先

- `.claude/skills/kiro-impl/SKILL.md` の `project-override` の印を付けた行
- `.gitattributes`
- `docs/conventions/workflow.md` の「コミット」
