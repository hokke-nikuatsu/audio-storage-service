# ADR-0003: 入口のファイルは案内だけにし、規約は作業の進め方とコードで置き場を分ける

## 背景と課題

このリポジトリのドキュメントは、人と複数の AI ツールの両方が読む。Claude Code は CLAUDE.md を、ほかの多くのツールは AGENTS.md を読む。規約をツールごとのファイルに複製すると内容が食い違い、同じことを複数の場所に書くと片方だけが古くなる。どこに何を書くかを決め、規約の置き場を1か所に定める必要がある。

## 検討した選択肢

### 入口のファイル（AGENTS.md）に規約の本文も書く

- 良い点: AI が必ず読む。ファイルが増えない
- 悪い点: 入口が肥大化する。入口を読まないツールや人には規約が届かない

### 入口は案内だけにし、規約はすべて steering に置く

- 良い点: 規約の置き場が1つになる。cc-sdd の skill が規約として読み込む
- 悪い点: steering は cc-sdd の作業領域（隠しディレクトリの `.kiro/`）にあり、コミットや PR のたびに人が参照する規約の置き場として見つけにくい

### 入口は案内だけにし、規約は作業の進め方とコードで置き場を分ける

- 良い点: 作業の進め方の規約は人が見つけやすい `docs/` に、コードに関する規約は cc-sdd が spec と実装の作業で読み込む steering に置ける
- 悪い点: 規約の置き場が2つになり、どちらに書くかの基準が必要になる

## 決定

「入口は案内だけにし、規約は作業の進め方とコードで置き場を分ける」を選ぶ。人が日常的に参照する規約は見つけやすい場所に置き、cc-sdd が使う規約は cc-sdd が読む場所に置けるため。

- AGENTS.md を AI の入口の正本にし、言語（応答と成果物）だけを書いて、作業の進め方の規約を `@` で取り込む。CLAUDE.md は AGENTS.md を取り込み、Claude Code 固有のことだけを書く。こうすると、どのツールにも同じ指示が AGENTS.md から届く
- 作業の進め方の規約（ドキュメントの置き場、開発の流れ、要件 ID、ブランチ、コミット、PR）は `docs/conventions/` に置く
- コードに関する規約（技術スタック、アーキテクチャ、コーディング規約）は `.kiro/steering/` に置く
- ADR は判断の理由だけを持ち、現時点の正は規約・steering・spec に置く
- ドキュメントの一覧と役割は、作業の進め方の規約の「ドキュメントの置き場」の表だけに書く。README は人の入口として、概要・起動方法と、その表へのリンクだけを持つ

## 影響

- 良い点: 規約の本文がそれぞれ1か所にだけあり、ツールが増えても入口から同じ規約にたどり着ける
- 受け入れたトレードオフ: 規約がどちらの置き場に属するか迷う場合がある。迷ったら「コードを読み書きするときに必要か」で判断し、必要なら steering に置く

## 見直し条件

- 同じ規約が `docs/conventions/` と steering の両方に書かれる事態が起きたら、どちらに置くかの判断基準（コードを読み書きするときに必要か）を見直し、その規約を性質に合う片方へ寄せる。作業の進め方とコードに関する規約は性質が違うため、置き場そのものは1つにまとめない
- AGENTS.md と CLAUDE.md の取り込みの仕様が変わり、Claude Code が AGENTS.md を直接読む形で足りるようになったら、CLAUDE.md の役割を見直す

## 反映先

- `docs/conventions/workflow.md` の「ドキュメントの置き場」
- `AGENTS.md`、`CLAUDE.md`、`README.md`
