# ADR-0009: Kotlin のコードは ktlint と detekt 2.0 で確かめ、コンパイラの警告をエラーにする

## 背景と課題

AI が書く Kotlin のコードについて、書き方のばらつきと、長すぎる関数・複雑すぎる分岐・命名規則の違反のような質の問題を、レビューの前に機械で止めたい。Kotlin は 2.3 系を使う（ADR-0007、`.kiro/steering/tech.md`）が、detekt の安定版 1.23 系は Kotlin 2.0 向けにビルドされており、2.3 系に対応した 2.0 系はアルファ版である。

## 検討した選択肢

### ktlint と detekt 2.0（アルファ版）

- 良い点: Kotlin 2.3 に正式に対応した版で、書き方（ktlint）と質（detekt）の両方を確かめられる
- 悪い点: アルファ版なので、設定の形やルールが正式版までに変わる可能性がある

### ktlint と detekt 1.23（安定版）

- 良い点: 安定版で、情報が多い
- 悪い点: Kotlin 2.3 のプロジェクトで動かすには、detekt が使う Kotlin のバージョンを固定する回避策が要るおそれがある。新しい文法を読み違える可能性がある

### ktlint だけ

- 良い点: 安定していて、設定がほぼ要らない
- 悪い点: 命名規則や複雑さを確かめられない

## 決定

「ktlint と detekt 2.0（アルファ版）」を選ぶ。使う Kotlin に正式に対応した版で、書き方と質の両方を確かめられるため。アルファ版でも、バージョンは Gradle で固定するので、意図せず変わることはない。

- Kotlin のコンパイラの警告をエラーにする（`allWarningsAsErrors`）。追加の道具なしで、使っていない変数や非推奨の API を止められるため
- ktlint と detekt のバージョンは、mise ではなく Gradle のプラグインとして固定し、`lefthook.yml` の `pre-push` から `./gradlew` で呼ぶ。CI も同じコマンドを呼ぶ（ADR-0005）

## 影響

- 良い点: 書き方と質の問題はチェックが止めるので、レビューは振る舞いと設計に集中できる
- 受け入れたトレードオフ: detekt の正式版が出たら、設定とルールの変更に合わせて直す必要がある。プッシュの前のチェックに Gradle の起動の時間が加わる

## 見直し条件

- detekt 2.0 のアルファ版が Kotlin 2.3 のプロジェクトで動かなければ、detekt 1.23 に回避策を入れて使うか、ktlint だけにする
- detekt 2.0 の正式版が出たら、正式版に上げる

## 反映先

- `.kiro/steering/tech.md`
- `docs/conventions/checks.md`、`lefthook.yml`（Gradle のプロジェクトを作るときに反映する）
