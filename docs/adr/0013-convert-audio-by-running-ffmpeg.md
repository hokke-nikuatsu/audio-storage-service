# ADR-0013: 音声の変換は ffmpeg のコマンドを直接起動して行い、形式は ffprobe で確かめる

## 背景と課題

送受信用の m4a（AAC）と保存用の WAV を相互に変換する（ADR-0012）。Java の標準ライブラリは PCM しか扱えず、Java だけで書かれた AAC のエンコーダもほぼないため、ネイティブのコードで書かれた変換の実装を使う必要がある。事実上の標準である ffmpeg を、どう呼ぶかを決める。

## 検討した選択肢

### ffmpeg のコマンドを直接起動する

- 良い点: 依存が増えない。別プロセスで動くので、変換が異常終了してもサービスは巻き込まれない。何をしているかがコマンドで明確
- 悪い点: 終了コード、標準エラー、タイムアウトを自分で扱う。ffmpeg の入った実行環境が要る

### Jaffree などのラッパー

- 良い点: コマンドの引数を型のある API で組み立てられる
- 悪い点: 使うコマンドは変換の2種類だけで、依存を増やす利点が小さい

### JAVE2

- 良い点: ffmpeg の実行ファイルを jar に同梱していて、別に入れなくてよい
- 悪い点: jar が大きく、同梱の ffmpeg のバージョンを選べない

### JavaCV（JNI）

- 良い点: プロセスを起動せず、プロセス内から ffmpeg のライブラリを呼べる
- 悪い点: ネイティブのライブラリが数百 MB になる。ffmpeg が異常終了するとサービスごと落ちる

## 決定

「ffmpeg のコマンドを直接起動する」を選ぶ。使うコマンドが2種類だけでラッパーの利点がなく、別プロセスにすることで変換の失敗をサービスから切り離せるため。

- ffmpeg とのファイルの受け渡しは、標準入出力ではなく一時ファイルで行う。m4a は目次（`moov`）をファイルの末尾に置くことが多く、読むにも書くにもファイルの前後を行き来する必要がある。標準入出力では行き来できず、行き来するには全体をためておく必要があるので、初めから一時ファイルで受け渡す
- 変換の前に、ffmpeg に付属する ffprobe で、コンテナが MP4、コーデックが AAC であることを確かめる。ffmpeg は入力の形式を自動で判別して変換してしまうので、m4a 以外を受け付けない（REQ-1.5）ため
- ffmpeg と ffprobe は、実行環境のイメージに入れる

## 影響

- 良い点: 変換の実装は `AudioConverter` のポートのアダプタに閉じ、手順のコードは ffmpeg を知らない（ADR-0010）
- 受け入れたトレードオフ: 変換のたびにプロセスの起動と一時ファイルの読み書きが加わる。アダプタのテストには ffmpeg の入った環境が要る

## 見直し条件

- 変換の同時実行が増え、プロセスの起動が応答時間の多くを占めるようになったら、変換を別のワーカーに切り出すかを検討する
