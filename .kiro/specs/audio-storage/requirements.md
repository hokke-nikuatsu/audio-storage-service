# Requirements Document

## Project Description (Input)
- 問題を抱えている人: 語学学習アプリで、用意された練習フレーズの中から選んだフレーズをモバイル端末に向かって声に出して練習し、あとからその録音を聞き返したいユーザー
- 現状: クライアント（モバイル端末）はさまざまなフォーマットで音声を送信・取得できるが、ユーザーとフレーズに紐づけて録音を保存し、取り出す仕組みがない
- 変えたいこと: ユーザーとフレーズに紐づく音声ファイルを受け取り、サーバー上では常に同じ1つのフォーマットに変換して保存し、取得時にはクライアントが求めるフォーマットに変換して返すバックエンドサービスを作る。保存は `POST /audio/user/{user_id}/phrase/{phrase_id}`、取得は `GET /audio/user/{user_id}/phrase/{phrase_id}/{audio_format}` で行い、どちらでも user_id と phrase_id がデータベースにある有効な ID かを確かめる。データベースには、有効なユーザー ID のテーブル、有効なフレーズ ID のテーブル、保存した音声ファイルのパスとユーザー ID・フレーズ ID の対応のテーブルを持つ。音声フォーマットは送受信用と保存用の2つだけを扱い、具体的な形式は技術選定で決める。サービスとデータベースは Dockerfile を使って手元のマシンで起動できるようにする

## Introduction
Audio Storage Service は、ユーザーが練習フレーズを声に出して録音した音声を受け取り、保存用フォーマットに変換して保存し、あとから送受信用フォーマットに変換して返す。録音はユーザー ID とフレーズ ID の組で見分け、1つの組につき最新の録音を1つだけ持つ。

## Boundary Context
- **In scope**: 録音の保存（同じ組への再保存は上書き）、録音の取得、ユーザー ID とフレーズ ID の検証、手元のマシンでの起動
- **Out of scope**: ユーザーとフレーズの登録・変更・削除と、ID 以外の属性。録音の削除・一覧・過去の録音の保持。リクエストを送ったのが本人かの認証と認可。保存したファイルの暗号化などの保護。送受信用と保存用以外のフォーマット
- **Adjacent expectations**: 有効なユーザー ID とフレーズ ID は、サービスの外で決まり、起動時の初期データとして用意される

## Requirements

### Requirement 1: 録音の保存
**Objective:** 練習するユーザーとして、あとから聞き返すために、練習したフレーズの録音をアップロードしたい

#### Acceptance Criteria
1. 有効なユーザー ID とフレーズ ID を指定して、送受信用フォーマットの音声ファイルが送られたとき、Audio Storage Service は音声を保存用フォーマットに変換して保存し、ユーザー ID とフレーズ ID の組に紐づけて記録する
2. 録音の保存が完了したとき、Audio Storage Service は保存に成功したことを示す応答を返す
3. すでに録音が保存されている組に新しい録音が送られたとき、Audio Storage Service は既存の録音を新しい録音で置き換える
4. 要求に音声ファイルが含まれていない場合、Audio Storage Service は何も保存せず、音声ファイルがないことを示すエラーを返す
5. 送られたファイルが送受信用フォーマットの音声として読めない場合、Audio Storage Service は何も保存せず、受け付けられないファイルであることを示すエラーを返す
6. 送られた音声ファイルが上限の大きさを超える場合、Audio Storage Service は何も保存せず、ファイルが大きすぎることを示すエラーを返す
7. 変換や保存が途中で失敗した場合、Audio Storage Service は失敗したことを示すエラーを返し、その組に既存の録音があればそのまま取得できる状態に保つ

### Requirement 2: 録音の取得
**Objective:** 練習するユーザーとして、自分の発音を聞き返すために、練習したフレーズの録音を取り出したい

#### Acceptance Criteria
1. 有効なユーザー ID とフレーズ ID と送受信用フォーマットを指定して録音の取得が要求されたとき、Audio Storage Service はその組に保存された録音を送受信用フォーマットに変換して返す
2. 指定された組に録音が保存されていない場合、Audio Storage Service は録音がないことを示すエラーを返す
3. 指定されたフォーマットが送受信用フォーマットではない場合、Audio Storage Service は対応していないフォーマットであることを示すエラーを返す
4. 録音の読み出しや変換に失敗した場合、Audio Storage Service は失敗したことを示すエラーを返す

### Requirement 3: ユーザー ID とフレーズ ID の検証
**Objective:** サービスの運用者として、存在しないユーザーやフレーズに録音を紐づけないために、登録されていない ID への保存と取得を拒みたい

#### Acceptance Criteria
1. 録音の保存または取得が要求されたとき、Audio Storage Service は録音を扱う前に、ユーザー ID とフレーズ ID が有効な ID として登録されているかを確かめる
2. ユーザー ID が有効な ID として登録されていない場合（ID の形式が正しくない場合を含む）、Audio Storage Service は録音を扱わず、ユーザーが見つからないことを示すエラーを返す
3. フレーズ ID が有効な ID として登録されていない場合（ID の形式が正しくない場合を含む）、Audio Storage Service は録音を扱わず、フレーズが見つからないことを示すエラーを返す

### Requirement 4: 手元のマシンでの起動
**Objective:** サービスを動かして確かめる人として、保存と取得を実際に試すために、サービスとデータベースを手元のマシンで起動したい

#### Acceptance Criteria
1. Audio Storage Service は常に、リポジトリに含まれる Dockerfile を使って、サービスとデータベースを手元のマシンで起動できる
2. サービスとデータベースが起動したとき、Audio Storage Service は有効なユーザー ID とフレーズ ID が初期データとして登録された状態で、保存と取得の要求を受け付ける

### Requirement 5: 指定された作り方の制約
**Objective:** サービスを動かして確かめる人として、決められた手順のとおりに試すために、決められた形で録音を保存して取り出したい

#### Acceptance Criteria
1. Audio Storage Service は常に、手元のマシンで起動したとき、ポートを指定しない `http://localhost/` で要求を受け付ける
2. Audio Storage Service は常に、保存の要求では音声ファイルを `audio_file` という名前のフォームのフィールドで受け取る
3. Audio Storage Service は常に、録音をサーバーのディスクにファイルとして保存する
4. Audio Storage Service は常に、データベースに、有効なユーザー ID の表、有効なフレーズ ID の表、保存したファイルのパスとユーザー ID・フレーズ ID の対応の表の3つを持ち、保存したファイルのパスを対応の表に記録する
